# HIPAA Security Rule Compliance Matrix

Avecinna is designed to satisfy the technical requirements of the **HIPAA Security Rule (45 CFR Part 164 Subpart C)**.

---

## Technical Safeguards Mapping (§164.312)

| HIPAA Regulation Section | Regulatory Requirement | Avecinna Technical Implementation |
| :--- | :--- | :--- |
| **§164.312(a)(1) Access Control** | Limit access to ePHI to authorized persons or software programs. | **CAAC Authorization Engine:** Enforces dynamic intersection of Role, Shift Window, Ward context, Care Team membership, and OPD scheduling. |
| **§164.312(a)(2)(i) Unique User ID** | Assign a unique name/number for identifying and tracking identity. | Every request resolves a unique `user_id` and embeds it immutably into `avecinna_audit_db` chained blocks. |
| **§164.312(a)(2)(ii) Emergency Access** | Establish procedures for obtaining ePHI during an emergency. | **Two-Tier Break-Glass Protocol:** Tier 1 instant 1-click critical vitals/allergy summary + Tier 2 full chart unlock with mandatory justification. |
| **§164.312(b) Audit Controls** | Implement hardware/software mechanisms that record and examine activity in ePHI systems. | **Isolated Cryptographic Audit Ledger:** Physically isolated PostgreSQL database storing chained SHA-256 blocks with Merkle DAG offline branch merging. |
| **§164.312(c)(1) Integrity Controls** | Protect ePHI from improper alteration or destruction. | **SHA-256 Content & Document Hashing:** Medical document uploads, lab results, and audit blocks compute SHA-256 binary checksums with tamper verification. |
| **§164.312(d) Person/Entity Auth** | Verify that a person seeking access to ePHI is the one claimed. | **JWT Authentication & Shift Roster Verification:** Cryptographically signed session tokens validated against active roster shifts (`ward_rosters`). |
| **§164.312(e)(1) Transmission Security** | Guard against unauthorized access to ePHI in transit. | **TLS 1.3 Encryption & Server-Side DTO Masking:** All transmission encrypted via TLS 1.3; unauthorized fields scrubbed before sending (OWASP API3 mitigation). |
