# Threat Model & Security Mitigations

Avecinna addresses the critical attack vectors highlighted in the **OWASP API Security Top 10 (2023)** and follows standard STRIDE threat modeling.

---

## 1. OWASP API Security Mitigations

### API1: Broken Object Level Authorization (BOLA / IDOR)
- **Attack Scenario:** Clinician `Doctor A` modifies the URL patient ID parameter to `p-peds-99` to read an unauthorized pediatric chart.
- **Avecinna Mitigation:** The CAAC engine intercepts the request, notes that `Doctor A` is assigned to `w-cardio` (not `w-peds`) and has no active care team consult or Break-Glass session on `p-peds-99`, and instantly rejects with `HTTP 403 Forbidden`.

### API3: Broken Object Property Level Authorization (Excessive Data Exposure)
- **Attack Scenario:** A ward clerk or pharmacist inspects browser DevTools Network tab to view confidential doctor progress notes transmitted in the background.
- **Avecinna Mitigation:** Backend `filterPatientRecordByRole()` scrubs unauthorized properties server-side. Clerks only receive demographics and bed allocations; Administrators receive clinical redaction notices (`[REDACTED - ADMIN PRIVACY RESTRICTION]`).

### API8: Security Misconfiguration (Ransomware Audit Deletion)
- **Attack Scenario:** Attackers compromise the primary operational database and execute `DROP TABLE audit_logs;` to wipe evidence.
- **Avecinna Mitigation:** Audit records reside in a physically isolated database (`avecinna_audit_db`) accessed via write-only credentials (`REVOKE UPDATE, DELETE, TRUNCATE`).

## 2. STRIDE Threat Matrix

| STRIDE Category | Threat Description | Avecinna Defense Mechanism |
| :--- | :--- | :--- |
| **Spoofing** | Off-duty clinician forging active shift identity | Signed JWT tokens + dynamic database lookup in `ward_rosters` table. |
| **Tampering** | Modifying historical audit blocks or medical documents | Sequential SHA-256 hash chaining + Binary Merkle tree root verification. |
| **Repudiation** | Clinician denies viewing a VIP patient's chart | Non-repudiable audit block recording `user_id`, `patient_id`, `ip_address`, and payload hash. |
| **Information Disclosure** | Lateral snooping across clinical wards | CAAC 4-factor authorization + Server-side role DTO masking. |
| **Denial of Service** | Flooding Break-Glass endpoints to lock system | Rate limiting (max 3 Tier-2 activations per clinician shift). |
| **Elevation of Privilege** | Nurse escalating to physician encounter creation | Strict backend role checks (`session.role === 'DOCTOR'`). |
