# Service Worker & Background Sync

The Avecinna Web Service Worker (`frontend/public/sw.js`) manages network resilience, caching, and background synchronization during clinical network drops.

---

## 1. Mutation Pass-Through Rule

::alert{type="warning"}
**Mutation Routing Rule:** Mutations (`POST`, `PATCH`, `PUT`, `DELETE`) must bypass service worker synthetic cache interception to ensure live transactions reach the backend directly without generating false `503 NETWORK_OFFLINE` errors.
::

```javascript
// frontend/public/sw.js
self.addEventListener('fetch', (event) => {
  const method = event.request.method;

  // Let all mutations pass directly to network without synthetic interception
  if (method === 'POST' || method === 'PATCH' || method === 'PUT' || method === 'DELETE') {
    return event.respondWith(
      fetch(event.request).catch(() => {
        // Enqueue into Background Sync queue if genuinely offline
        return queueOfflineMutation(event.request);
      })
    );
  }

  // Read requests (GET) utilize stale-while-revalidate / local cache
  event.respondWith(handleReadRequest(event.request));
});
```

---

## 2. Background Reconnection Synchronization

When the browser fires the `online` event:
1. The Service Worker flushes pending offline audit blocks to `/api/v1/audit/reconcile-offline`.
2. The server processes the branch and returns the new Merkle DAG merge commit.
3. In-memory and IndexedDB clinical caches are re-synchronized with central PostgreSQL.
