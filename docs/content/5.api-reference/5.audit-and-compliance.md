# Audit & Cryptographic Compliance API

Endpoints for querying forensic audit blocks from the isolated database (`avecinna_audit_db`) and validating cryptographic proofs.

---

## 1. Query Audit Blocks (Chained Ledger)

`GET /api/v1/audit/blocks`

### Query Parameters
- `limit` (default: 50)
- `offset` (default: 0)
- `userId` (optional filter)
- `patientId` (optional filter)
- `action` (optional filter)

### Response (200 OK)
```json
{
  "total": 128,
  "blocks": [
    {
      "indexNum": 128,
      "blockHash": "c492...81a0",
      "prevHash": "9b12...44f1",
      "userId": "u-doc-cardio",
      "patientId": "p-cardio-01",
      "action": "PATIENT_VIEW_SUCCESS",
      "activeWard": "w-cardio",
      "payloadHash": "e3b0...b855",
      "ipAddress": "192.168.1.45",
      "deviceType": "DESKTOP",
      "executionMode": "MODE_A",
      "timestamp": "2026-09-20T21:15:30.000Z"
    }
  ]
}
```

## 2. Verify Cryptographic Ledger Integrity

`POST /api/v1/audit/verify`

Iterates sequentially through all blocks in `avecinna_audit_db`, recomputing every SHA-256 block hash from origin genesis to tail.

### Response (200 OK - Untampered)
```json
{
  "valid": true,
  "status": "VERIFIED",
  "totalBlocks": 128,
  "tamperedBlockIndex": null,
  "latestBlockHash": "c492...81a0"
}
```

### Response (200 OK - Tampering Detected)
```json
{
  "valid": false,
  "status": "TAMPERED",
  "totalBlocks": 128,
  "tamperedBlockIndex": 42,
  "expectedHash": "4a12...89be",
  "actualHash": "9999...0000"
}
```

---

## 3. Reconcile Offline Ward Audit Branch

`POST /api/v1/audit/reconcile-offline`

Merges an array of offline audit blocks into the central Merkle DAG by creating a dual-parent merge commit.

### Request Body
```json
{
  "wardId": "w-field-clinic-01",
  "offlineBlocks": [
    {
      "blockHash": "off-hash-01",
      "prevHash": "ancestor-hash-00",
      "action": "OFFLINE_VITALS_RECORD",
      "userId": "u-nurse-field",
      "timestamp": "2026-09-20T19:00:00.000Z"
    }
  ]
}
```
